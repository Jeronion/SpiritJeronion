

## Единый запуск SpiritJeronion

Для управления всем проектом используется один пользовательский файл: `launcher/SpiritJeronion.cmd`. Дважды щёлкни его и выбери `1` для запуска или `2` для остановки. При запуске включаются n8n, МЭШ, content worker, Telegram-бот, локальный сайт и Cloudflare Quick Tunnel. После запуска открывается GitHub Pages, а новый tunnel URL и `SPIRIT_QUEUE_SECRET` сохраняются только в `localStorage` текущего браузера.

Секрет не записывается в GitHub Pages и не отправляется GitHub: конфигурация передаётся через URL fragment (`#setup=...`), который браузер не включает в HTTP-запрос, а затем сразу удаляет из адресной строки.

Внутренние PowerShell-скрипты находятся в `launcher/internal`; запускать их вручную не требуется.

GitHub Pages публикуется автоматически workflow из `.github/workflows/pages.yml` после push в `main`; локальный launcher не создаёт автоматических Git-коммитов.

## Текущая версия

- Весь сайт находится в `WebsiteHosting`; GitHub Actions публикует эту папку в GitHub Pages.
- Интерфейс показывает очередь, источник и доказательства, позволяет подтвердить или отклонить предложение и содержит чат с Groq.
- Календарь читается из `WebsiteHosting/data/calendar.json`.
- Сводка задач читается из `WebsiteHosting/data/tasks.json` и отображается по четырём квадратам Эйзенхауэра.
- Конспекты и решения ДЗ хранятся как Markdown в `WebsiteHosting/data/notes` и `WebsiteHosting/data/homework`.
- Workflow: `MCPtools/n8n/SpiritJeronion-vNext-skeleton.json`.
- API очереди: `POST /webhook/sj-queue`.
- Решение пользователя: `POST /webhook/sj-queue-decision`.
- Чат: `POST /webhook/sj-chat`.
- Во всех запросах сайта секрет передаётся полем `secret` и сравнивается с `SPIRIT_QUEUE_SECRET`.
- Адрес n8n и секрет сохраняются только в localStorage браузера и не попадают в Git.
- Gmail и Telegram collectors пока отключены в workflow. Их следует включить только после настройки credentials и отдельного решения об отправке содержимого сообщений в Groq.
- После подтверждения календарь, задачи, конспекты и решения обрабатывает `MCPtools/content_worker`.
- Для автоматической записи новых данных в GitHub worker использует отдельный fine-grained `GITHUB_TOKEN` с доступом Contents: Read and write только к репозиторию `Jeronion/SpiritJeronion`.
- ChatGPTAutomation запускает видимый Chrome. Библиотека установлена, но до ручного входа должна оставаться с `CHATGPT_AUTOMATION_ENABLED=false`.

## Подключение сайта

1. Запустить n8n и постоянный Cloudflare Tunnel.
2. Открыть сайт и перейти в «Настройки».
3. Вставить публичный HTTPS-адрес n8n без `/webhook`.
4. Вставить значение `SPIRIT_QUEUE_SECRET` из локального корневого `.env`.
5. Нажать «Проверить», затем «Сохранить».

## План ассистента

### 1. Составление событий в календаре
- Он должен составлять события в календаре в зависимости от того что написано в почте, в его расписании, и в телеграм чатах.

### 5. Отслеживание изменений расписания
- Он должен уметь отслеживать изменения расписания в зависимости оттого что написано в чатах или в почте и придупреждать о них.
- После моего подтверждения заносить изменения в календарь.


### 2. Отслеживание задач (таски)
- Он должен отслеживать, что я должен сделать, например я пишу ему что у меня намечается какая-то задача, например исправить двойку, и он заносит её в таски.
- Причём таски должны быть рандированы по схеме 4 квадратов.


### 3. Отслеживание домашнего задания
- Он должен отслеживать моё домашнее задание, в МЭШ, в почте, в телеграм чатах, также я должен иметь возможность прислать ему распечатку разданную на уроке, а он её должен прикрепить как дз или как (4 пункт).


### 4. Ведение конспектов по предметам
- Он должен вести конспекты по предметам в зависимости от того что написано в дз (например: задания типа, прочитать 153-168стр учебника, или сделать конспект темы), что есть в учебнике (все учебники должны быть у него скачаны), и он должен уметт его делать по распечаткам которые я прислал (из 3 пункта).
- Конспекты должны быть оформлен ввиде файлов .md с ссылками на страницы учебника или распечатку.

### 6. Выполнение домашних заданий и генерация конспектов
- Он должен уметь выполнять домашние задания за меня, закидывать их в чат гпт вместе с распечатками.
- Также хотелось бы чтобы при необходимости принести конспект в качестве дз он мог моим почерком сделать мне фотки страниц конспекта, чтобы я их мог распечатать.


### Дополнительные требования к интерфейсу и подтверждению действий
- Интерфейс должен быть удобно реализован, я должен всегда иметь возможность перепроверить что мне говорит ИИ (именно для этого он должен отчитываться откуда пришла инфа и по возможности кидать ссылку на нееё).
- Любые изменения в тасках или в календаре он должен делать только после моего подтверждения, для этого должна быть организована очередь изменений, в каждой из которых описано что он изменит и почему (см. пункт выше), а также возможность подтвердить или отказаться.
